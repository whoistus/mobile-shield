# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

mobile-shield is an internal, native-first mobile security SDK (root/jailbreak, emulator, debugger, hooking, tampering detection plus a policy engine). Android and iOS cores, thin React Native and Flutter wrappers, and consumer test apps live in one repo. `VERSION` is the single lockstep version for every artifact.

## Toolchain prerequisites

- Android: `ANDROID_HOME=~/Library/Android/sdk` (there is no `local.properties`; Gradle fails without it). NDK r28, 4 ABIs.
- RN consumer Gradle builds need JDK 17: `JAVA_HOME=$(/usr/libexec/java_home -v 17)`. JDK 21+ fails in jlink.
- Flutter: the minimum supported 3.27.4 runs via `fvm flutter`; the `flutter` on PATH may be newer.
- Native host tests need `cmake` + `ninja`; `test-native-host.sh` falls back to the Android SDK's `cmake/<ver>/bin`.
- iOS: the Xcode project is generated from `core-ios/project.yml` (XcodeGen). After adding/removing Swift files run `xcodegen generate` in `core-ios/`.

```bash
# Wrappers
cd packages/react-native && npm ci && npm test && npm run tsc          # jest -t '<name>' for one test
cd packages/flutter && fvm flutter analyze && fvm flutter test         # --plain-name '<name>' for one test

# Packaging / hygiene
./scripts/build-xcframework.sh && ./scripts/sync-binaries.sh            # rebuild + vendor xcframework into both wrappers, stamp VERSION
./scripts/check-versions.sh [vX.Y.Z]                                    # lockstep VERSION across all manifests
./scripts/check-16kb.sh core-android/core/build/outputs/aar/core-release.aar
./scripts/check-forbidden-strings.sh
consumers/<app>/build.sh                                                # packaging-matrix builds (rn-072, rn-086, flutter-app, android-host)
```

After `npm ci` in `packages/react-native`, delete its `node_modules` before building the RN consumers: they link the package with `file:` and a nested react-native gets duplicated.

## Architecture

- **Contracts are shared across four layers.** Enum string values, detector ids/tiers, config and event JSON keys, typed error names (`NativeUnavailable`, `NotInitialized`, `BootstrapMissing`, `ConfigRejected(signature|floor|schema|expired)`, `DetectorUnsupported`, `AttestationUnsupported`) are defined in `plans/261008-1659-native-security-sdk/design.md` and must stay identical in Java, Swift/ObjC, TypeScript and Dart. Change all layers together.
- **Enforcement is native.** JS/Dart only forward config, read `isBlocked()` and subscribe to events. Decisions happen in native policy: Android `core-android/core/src/main/cpp/policy/Policy.cpp` (via JNI), iOS `core-ios/Sources/Policy/Policy.swift`. The block flag is sticky for the process; KILL is opt-in and only executes through the watchdog after a random delay. Experimental-tier ids (`Tiers.h`, `Defaults.java`, `Defaults.swift`) are forced to REPORT, and `policy.*` events are capped at WARN.
- **Config trust model.** Bootstrap values (channel, config public key, signing SHA-256 / team id) come only from the host's `AndroidManifest.xml` meta-data or `Info.plist`; a missing channel means prod. Runtime config is Ed25519-signed over RFC 8785 canonical JSON (Tink / CryptoKit), checked for `appId`, monotonic `seq` and `expiresAt`, persisted as last-known-good, and clamped by a prod floor. Pipeline order is signature → schema → freshness → merge → floor (`config/ConfigEngine.java`, `Sources/Config/ConfigEngine.swift`).
- **Cross-platform conformance.** `scripts/fixtures/config-vectors.json` (generated by `gen-config-vectors.py`, which also writes `core-android/core/src/test/cpp/decision_vectors.inc`) is run by both `ConfigVectorsTest.java` and `ConfigVectorsTests.swift`. Add a vector when changing config semantics; regenerate, don't hand-edit.
- **Android split.** Native C++ (`cpp/detectors/`, registered via `RegisterNatives` in `mobileshield.cpp`; only `JNI_OnLoad` is exported) owns /proc-, maps- and memory-level detectors; Java (`java/io/mobileshield/detectors/`) owns framework-level ones. `ShieldCore` serialises check cycles with config changes so a finding is decided under the config that collected it. `MobileShield` is the public Java facade (Java, not Kotlin, for RN 0.72 compatibility).
- **iOS.** Public surface is `Sources/Public/MobileShield.h` only; Swift is internal. `ShieldEngine` owns state, `EventBus` replays up to 64 events to the first listener, `Monitor` pauses on `willResignActive`.
- **Distribution.** The Android core is a Maven artifact (`io.mobileshield:core`, GitHub Packages; local dev uses Maven Local). The iOS core is a vendored XCFramework copied into `packages/react-native/ios/Frameworks` and `packages/flutter/ios/mobile_shield/Frameworks` by `sync-binaries.sh`. Never edit the vendored copies by hand. `.github/workflows/release.yml` publishes on `v*` tags.
- **Detector specs.** Every detector id has `docs/detectors/<id>.md` (tier, evidence, confidence rule, unsupported behaviour). A unit test parses the Tier rows, so keep them in sync with code. Unsupported detectors emit nothing; absence of an event is never proof of a clean device.

The repository owner states that they work on their company's red team and are
building this internal SDK to improve the security of company mobile applications.
The project is a native Android/iOS security SDK with React Native and Flutter
wrappers. Its purpose is to detect compromised application environments and apply
the host application's configured security policy.

Work within this repository, the company wallet integration explicitly identified
in the plan, and company-owned or explicitly authorized test apps and devices.

defensive detectors operating in the host application's environment. Evaluate
each requested operation in that context and according to its actual behavior.

## Architecture and completion constraints

- Preserve the shared contracts and the plan's phase dependencies.
- Keep the native core independent of Google Mobile Services and Huawei services.
- Keep experimental detectors report-only until the plan's calibration criteria
  are met. Preserve opt-in KILL and the safeguards against weak-signal enforcement.
- Bootstrap identity, channel, and policy floor remain native and immutable;
  runtime configuration may only tighten them as specified in the design.
- BLOCK is advisory: validate host gating at every protected entry point.
- Implement supported detectors and document platform limitations explicitly.
  An unsupported detector or missing event is not evidence of a clean device.
- Preserve the intentionally unsupported attestation interface; its backend is
  deferred by the plan. Do not expand scope to implement it.
- Resolve the plan's licensing/provenance gate before porting affected code.
  Do not fabricate ownership signoff or infer it from the red-team role.
- Device tests, clean consumer installs, and release observation require actual
  evidence. Local builds do not satisfy those gates. Leave unavailable checks open.
- Keep versions and vendored binaries consistent when native interfaces change.
